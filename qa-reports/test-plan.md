# Test Plan
Generated by /plan-eng-review on 2026-09-21
Branch: main

Desktop Electron app, local-only core. There are no URLs; "routes" below are
app views. Test stack: Vitest (units) + Playwright for Electron (window flows),
with a separate build-blocking security suite.

## Affected Pages/Routes

- First-run / onboarding — vault passphrase creation, Full Disk Access request,
  and the honest "no passphrase recovery exists" warning. Verify the app is
  usable and states its limits when FDA is denied.
- Triage view — bucketing by abuse score, blur toggle, batch actions. Verify
  hiding a message never removes it from the vault.
- Thread detail — edit chronology rendering, retraction markers, and WAL-recovered
  text shown with its provenance and capture time.
- Export view — hash verification, raw-record round-trip, complete access log.
- OSINT view — locked by default; unlock only for a vault sender above the abuse
  threshold; ranked hypotheses with visible supporting signals, never a bare name.
- Settings — IMAP/OAuth setup, model status, destroy-everything.

## Key Interactions to Verify

- Panic-hide hotkey hides the window immediately, with no preview left in the
  dock, window switcher or thumbnail.
- Batch-hide across 200+ messages, then confirm every message is still present
  and hash-verifiable in the vault.
- Destroy-everything requires an exact typed confirmation; a typo destroys nothing.
- OSINT unlock attempt on a sender who never messaged the user is refused.
- OSINT unlock attempt on a below-threshold sender is refused.
- Blur state persists across app restart and is never confused with deletion.

## Edge Cases

- chat.db locked by Messages.app mid-read: retry, do not fail the whole ingest.
- WAL checkpointed before capture: record a visible missed-capture event, never
  a silent skip.
- Malformed message_summary_info bplist: quarantine that record, keep the rest,
  surface the quarantine count in the UI.
- Schema change from a macOS update: quarantine and report, do not crash.
- Ollama absent or not running: summaries degrade, ingest and triage keep working.
- ONNX model file missing: clear actionable error, not a blank triage view.
- Wrong vault passphrase and a corrupted vault must be indistinguishable in both
  message text and response timing.
- Disk full mid-append: no partial or unhashed record is committed.
- OAuth refresh token expired: prompt re-auth, do not silently stop polling.
- Zero OSINT candidates found: say so plainly, do not present a weak lead as an answer.
- Non-English, emoji-only, and very long messages through the classifier.

## Critical Paths

1. Ingest -> hash at acquisition -> append-only vault -> export with verifiable
   hash and complete access log. This is the chain of custody. If it breaks, the
   evidence feature is worthless.
2. Abuser retracts a threat -> WAL watcher captures the text pre-checkpoint ->
   stored and marked as WAL-recovered. Highest-value evidence in the product.
3. Hide/blur a message -> message remains intact and retrievable in the vault.
   A regression here loses a restraining order.
4. OSINT gate refuses every subject not bound to an abusive vault sender,
   including via direct IPC and via homoglyph or normalization tricks.
5. Panic-hide under a real window manager, with no residual preview.

## Evals

- Coercive-control recall on the hand-authored DV set. Gate: if the ONNX
  classifier scores under 0.6 recall, detection moves into the local LLM.
- Escalation-trend summary quality on multi-message threads.
- False-positive rate on benign intimate conversation, which shares vocabulary
  with abusive conversation and is the likeliest source of harmful misfires.

## Fixture Rule

Every fixture is synthetic or from a consenting author. No real person's abuse
enters this repository. Fixture files are permanent once committed.
