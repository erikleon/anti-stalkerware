## Scope

Cross-platform readiness (D1's narrowed scope: "the app runs correctly on
whatever OS someone has," not multi-device sync) plus two bugs the audit
surfaced along the way. New ingest vectors (Instagram, payment apps) were
scoped and deferred — TODOS.md items 15/16 — not built, so nothing below
covers them.

## User flows

- **iMessage onboarding, default path untouched**: Settings -> Connect
  iMessage -> Scan (no field edited). Was always broken; not fixed for
  Scan-with-real-data (no real chat.db in CI), but `expandHome` is
  unit-verified as the correct fix for the specific defect found.
- **Support screen, hotkey status**: reachable both pre-passphrase (lock
  screen's Help link) and from the app nav post-unlock. Covered for the
  pre-passphrase path in `lock-and-triage.spec.ts`; the post-unlock path
  renders the same component, not separately tested (same render fn, same
  IPC call — a second test would be duplicate coverage, not new signal).

## Edge cases

- `expandHome`: bare `"~"`, `"~/..."`, `"~\\..."` (Windows-style, unlikely
  input but handled), an absolute path, a relative path with no `~`, and a
  `~` that isn't the leading character (must NOT be treated as a home-dir
  reference) — all covered in `test/unit/main/paths.test.ts`.
- Hotkey status: only the success path is exercised (see GAP above).

## Critical paths

- CI (`.github/workflows/test.yml`) must pass on all three OSes before
  this is genuinely "verified cross-platform" rather than "believed
  cross-platform" — the actual verification is CI's job going forward,
  not this local pass, which only ran on macOS.
